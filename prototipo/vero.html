O ecossistema

Seis portas. Um motor que aprende com todas.

Cada produto atende uma pessoa diferente, mas todos falam com o mesmo Vero Core. O golpe que a Dona Marlene denuncia de manhã vira bloqueio na extensão e na API à tarde.

      Arquitetura · sugestão, não decisão
      
Java no coração, rápido na borda, simples para começar.

      
Uma base que um time de cinco pessoas consegue operar no semestre e que aguenta crescer sem reescrever.

    

    

      
RECOMENDADO
A · Monólito modular
Um deploy com Spring Modulith. Cada produto é um módulo com fronteira verificada em teste; eventos internos viram Kafka quando um módulo precisar escalar sozinho.
Custo: disciplina de fronteiras desde o primeiro dia.

      
B · Microsserviços já
Deploy e escala independentes por produto. Lindo no diagrama.
Custo: cinco pessoas operando oito serviços gastam o semestre em infraestrutura.

      
C · Serverless
Barato quando ninguém usa. Bom para o bot e para webhooks.
Custo: cold start em Java, dependência do provedor e estado do jogo mais difícil.

@Service
class LinkRiskService {
  private final List<ThreatFeed> feeds;
  private final VerdictCache cache;

  LinkRiskService(List<ThreatFeed> feeds, VerdictCache cache) {
    this.feeds = feeds;
    this.cache = cache;
  }

  Verdict check(URI url) throws InterruptedException {
    var cached = cache.find(url);
    if (cached.isPresent()) return cached.get(); // ~ms
    try (var exec = Executors.newVirtualThreadPerTaskExecutor()) {
      var tasks = feeds.stream()
          .<Callable<Signal>>map(f -> () -> f.lookup(url)).toList();
      var verdict = Verdict.combine(exec.invokeAll(tasks, 250, MILLISECONDS));
      cache.put(url, verdict);
      return verdict;
    }
  }
}
